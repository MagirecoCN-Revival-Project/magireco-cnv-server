# 魔法纪录 服务端

魔法纪录国服复刻计划的**服务端**：主节点（API／账号／存档／握手）与边缘节点（静态资产分发）。

单个 Go 二进制，一个数据库，没有 Redis、消息队列或前端构建链——**目标是能被业余
志愿者在一台小机器上跑起来**。

📖 **完整文档：[docs.magireco.top/server](https://docs.magireco.top/server/)**（源码在 [`docs/`](docs)）

## 快速开始

```bash
go build ./...
go test ./...

CNV_DB_URL="./data/m.db" \
CNV_ADMIN_JWT_SECRET="至少16个字符的随机串" \
go run ./cmd/node
```

首次启动会自动跑迁移、生成并持久化节点密钥与 `resource_token` 签名密钥。
数据库三选一：PostgreSQL / MySQL / SQLite，`CNV_DB_URL` 决定用哪个。

部署（含 systemd unit 与边缘节点模板）见 [自托管指南](https://docs.magireco.top/server/self-host/)。

## 仓库结构

| 目录 | 内容 |
|---|---|
| `cmd/node` | 节点：`runBusiness`（DB + 全部 API + 调度器）/ `runEdge`（资产分发） |
| `cmd/panel` | 面板：节点注册表 + WebSocket 管控连接器 + 管理 UI |
| `internal/api/client` | `/client/*` 协议接口（握手、心跳、场景清单） |
| `internal/api/{account,user,admin,captcha,setup}` | 各业务域 |
| `internal/store` | 方言抽象 + 全部 SQL + 内嵌迁移 |
| `internal/directory` | Ed25519 签名的节点目录 |
| `internal/{auth,middleware}` | 哈希／令牌／鉴权／限流／受信任代理 |
| `internal/{scheduler,packer,capworker}` | 后台任务／打包／PoW 验证码 |
| `web/` | 面板前端：免构建 JSX，改完刷新浏览器即生效 |
| `docs/` | VitePress 文档站 |

## 协议以文档仓库为准

线格式的**唯一权威来源**是 `magirecocn-architecture-protocol-document`。

实现与文档冲突时**以文档为准**——改实现或提议改文档，**不要让文档迁就实现**。
文档中每项带状态标记：**✅ 已定 / 📝 草案 / 🚧 保留**。
🚧 **保留 = 明令未定，禁止自行发挥**，遇到它挡路时去把那一项定掉。

本仓库的 `docs/` 是**派生物**，不是真理来源；但它必须与实现保持一致。

> 早期代码注释写着「字段名以 `magireco-cnv-client` 的 Java 源码为唯一真理」。
> **该锚点已失效**——Android 客户端已弃维，不再有「照着实现」的对象。

## 服务端是唯一权威

客户端跑在玩家浏览器／设备里，源码与运行时状态对玩家完全开放、可随意改写。
**因此客户端的任何校验都没有安全意义**——那些校验只是为了少发一次注定失败的请求。

不得因为「客户端已经校验过」而省略任何服务端校验：

- **资产路径**：客户端已规范化并拒绝 `..`，服务端仍须独立做穿越防御（含百分号解码后的形态）。
- **状态同步键**：客户端有端点白名单，服务端**必须复刻同一套**——存档下行数据会被
  客户端直接写入本地状态库，服务端不校验等于把「写入任意键」的能力交给任何能伪造
  上行请求的人。
- **数据归属**：账号只能读写自己的数据。这条客户端完全无法保证。
- **业务合理性**：凡「客户端报什么就存什么」的端点，必须有服务端侧的合理性上界校验。

> ⚠️ **不要重建已知的洞**：现有 Android 生态里，战斗结算由客户端算完上报，服务端既无
> 随机种子也无逐回合轨迹，因而无法复现或校验——伤害、通关、掉落均可伪造。
> 新服务端须校验伤害／回合／耗时与关卡定义的一致性上界，**掉落由服务端裁定**
> 而非采信上报。

## 能力隔离

节点目录用 Ed25519 签名下发，客户端据此按 `caps` 路由：

- **边缘节点**只承担 `resource`，**不得**接收或校验登录／账号／存档凭证；
- **主节点**承担 `login`／`account`／`save`／`api`。

`caps` 声明**必须与实际部署一致**——声明了不具备的能力，等于把凭证引向错误的地方。

两处极易实现错、务必留意：

1. **节点目录的签名对象是 `payload` 字符串的原始字节**，不是重新序列化后的 JSON。
   签名之后再格式化 JSON，验签必然失败。
2. **资产未命中必须返回 404**，不要返回 `200` + 错误页——客户端会把它当作资产内容缓存下来。

## 资产与密钥不进版本库

服务端**持有并分发**游戏资产，但**资产不进 git**：存于对象存储／数据卷，由部署期
挂载或同步，仓库里只有拉取与校验脚本。测试固件须使用**自制的**占位数据（`testdata/`）。

**密钥同样永不入库。** 尤其是节点目录的 Ed25519 签名私钥——它是客户端信任链的根，
一旦泄漏，攻击者即可伪造节点目录、把玩家的登录与存档流量导向自己的节点。
**该私钥不得出现在任何在线服务上**，签名应在离线或受控环境完成。

配置一律经环境变量或部署期密文注入；源码中保持空值，且**缺失时拒绝启动**，
不得回退到默认端点或默认口令。

## 项目性质

魔法纪录官方服务已全部终止，本项目属于**非商业的保存性复刻（preservation）**。

Android 客户端（`magireco-cnv-client`）是**已过时的产物，不再维护**；
当前的客户端是 Web 端引擎（`magireco-web-client`）。
